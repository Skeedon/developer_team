# Этапы задачи: UI и контракт интеграции

В карточки добавлена шкала из пяти этапов: назначение исполнителей, разработка, тестирование и исправления, Reviewer, публикация PR. Завершённые этапы отмечены галочкой, текущий выделен, ошибочный отмечен знаком «!», ожидающие пронумерованы. Без PR последний этап перечёркнут и подписан для screen reader как пропущенный. На экранах до 480 px шкала вертикальная. Сохранены тёмные цвета, reduced motion, текстовые обозначения состояний и существующие действия карточек.

## Контракт для следующего этапа разработки

UI читает необязательное поле `currentStage` из ответа существующего `/api/tasks`:

| Значение | Этап |
| --- | --- |
| `assignment` | Назначение исполнителей |
| `development` | Разработка всех назначенных исполнителей |
| `testing` | Тестирование и исправления |
| `review` | Reviewer |
| `publication` | Публикация PR |

`status` остаётся источником состояния задачи. При `failed` сохраняйте `currentStage` места ошибки. При повторной публикации `publish_queued`, `publishing` и `publish_failed` UI всегда показывает публикацию; предыдущие этапы остаются завершёнными. При `completed` шкала завершена, публикация пропущена при `createPullRequest=false` и отсутствии URL PR.

Для исторических задач поддерживаются очередь, публикация, завершение и проверки со статусом `running`. Если этап выполняющейся или ошибочной задачи неизвестен, UI показывает «Этап не указан», не приписывая завершение предыдущим этапам.

`participants` поддерживает существующую строку через запятую и массив ролей. Показываются назначенные Developer/Designer и роль Reviewer. Если исполнители ещё не назначены, отображается пояснение. Одна роль Developer/Designer в старом поле `role` используется как fallback. Сведения о фактической активности каждого участника не выдумываются.

Backend/Worker и миграция не входят в этот UI-этап по последней инструкции пользователя: их интегрирует разработчик в том же workspace. Потребуются сохранение этапа до каждой операции, отдача поля через оба API задач, совместимость БД и серверные тесты ошибок/повторов.

## Проверки

- `node --check src/DeveloperTeam/wwwroot/dashboard.js` — успешно.
- `node tests/ui/dashboard.test.cjs` — 9 тестов успешно, включая переходы отображения, ошибки, повтор публикации, старые записи, задачи без PR, состав команды и существующие действия.
- `git diff --check` — успешно.
- Браузерная проверка не выполнена: браузер в среде отсутствует. Тесты используют mock DOM/API.

Публикация не выполнялась согласно запрету push/publish в инструкции. GitHub Draft PR не создан; один общий Draft PR следует подготовить после интеграции backend при наличии разрешения на публикацию.
